## Executive Summary

The site is a **single-page Next.js App-Router site on Vercel**, technically clean (HTTPS, HSTS, no mixed content, JS-rendered) but **missing every SEO foundation that a brand-new site needs to be indexable, shareable, and rankable**.

### Health score (out of 100)
| Area | Score | Verdict |
|---|---|---|
| Crawlability / Indexation | **35** | No robots.txt, no sitemap, no canonical, naked-domain duplicates www |
| Technical foundations | **70** | Vercel-fast, HTTPS, HSTS — but `metadataBase` points to a wrong URL |
| On-page (titles/meta/headings) | **55** | Title good, OG missing image, no Twitter image, multiple `<h2>` competing for one keyword |
| Schema / Structured data | **40** | A `Person` JSON-LD exists but lacks `url`, `image`, `worksFor`, `description`, `knowsAbout` |
| Content quality / E-E-A-T | **75** | Strong proof (3 exits, FT100, named cases) — but no /about, /work, /writing pages to deepen E-E-A-T |
| Authority / links | **20** | No GSC, no Bing, no schema for podcasts (which are great backlink fodder), single page = no internal linking equity |
| **Overall** | **49** | Foundation hot-fix needed before ANY off-site SEO work has effect |

### Top 5 critical issues (fix first, in this order)

1. **No `robots.txt` — Google sees a 200-status soft-404 SPA when it tries `/robots.txt`.** That alone won't block indexing, but it sends a "this site doesn't care about SEO" signal and stops you ever submitting a real sitemap.
2. **No `sitemap.xml`.** Without one, Google has to discover URLs by crawling alone — slow, lossy, and currently you only have one URL to discover anyway. A sitemap with `lastmod` is also the single biggest "please re-index me" signal for content changes.
3. **No `<link rel="canonical">`.** Google currently sees the homepage at five+ canonical-equivalent URLs (`https://www.meethayat.com/`, `https://meethayat.com/`, `?utm_*` variants, hash-anchor variants when shared). Ranking equity is split.
4. **`metadataBase` is wrong** — it's set to `https://hayat-amin-site.vercel.app` in `app/layout.tsx`. Every `og:url`, every absolute path Next builds, every social share preview will potentially leak that staging URL. Also a mild duplicate-content risk (the staging URL is publicly reachable on Vercel's preview domain).
5. **No `og:image` / `twitter:image`** — every LinkedIn, Twitter, WhatsApp, Slack, iMessage share renders a generic blank card. Given Hayat's audience is acquired via LinkedIn DMs and warm intros sharing this URL, this is the **single highest-leverage SEO/social fix on the page**.

### Quick wins (≤ 30 min each, deploy today)

- `app/robots.ts` (10 lines)
- `app/sitemap.ts` (10 lines)
- `app/opengraph-image.tsx` (auto-generated 1200×630)
- Fix `metadataBase` → `https://www.meethayat.com`
- Add `alternates: { canonical: "/" }`
- Add `twitter.card: "summary_large_image"`
- Add Google Search Console + Bing Webmaster verification meta tags
- Add naked → www 301 in `next.config.js` redirects
- Enrich `Person` JSON-LD with `url`, `image`, `description`, `worksFor`, `knowsAbout`, `sameAs[]`

### 1.2 Indexation & Canonicalisation

| # | Finding | Severity | Evidence |
|---|---|---|---|
| T6 | **No `<link rel="canonical">`** anywhere | 🔴 High | head dump of live HTML |
| T7 | **`https://meethayat.com/` and `https://www.meethayat.com/` BOTH return 200** with identical content (76,351 bytes each) and identical `etag` (`9447b3ecb9654f19431bd7d35cbf90a4`) | 🔴 High | `curl -sLI` on both |

- Add `<meta name="robots" content="noindex">` on the Vercel preview domain via a host-aware metadata helper (or block via Vercel project setting "disable preview deployment indexing").

## 2. ON-PAGE SEO

### 2.1 Title tag

```html
<title>Hayat Amin — Fractional CFO. IP &amp; data strategist. AI agent operator.</title>
```

| # | Finding | Severity |
|---|---|---|
| O1 | **86 characters** — will be truncated in SERP (~60 char visible) to roughly *"Hayat Amin — Fractional CFO. IP & data strategist. AI agent oper…"* | 🟡 Medium |
| O2 | Brand name first — fine for brand SEO ("Hayat Amin" search) but suboptimal for service-keyword SEO ("fractional CFO London", "IP strategist for tech") | 🟡 Medium |

### 2.6 Keyword targeting

The page currently competes for these implicit query types:
1. **Brand:** "Hayat Amin" — should rank #1 immediately once indexed
2. **Service + location:** "fractional CFO London", "fractional CFO NYC", "fractional CFO Dubai" — currently ZERO chance because the cities only appear in a JSON-LD address array, not in body copy or headings
3. **Service + niche:** "IP strategist for tech", "patent commercial grading", "AI agent operator", "fractional CSO" — the body copy mentions these but no `<h2>` or URL targets them
4. **Authority + topic:** "fractional CFO with exits", "CFO who took Cake to American Express" — body has it, no schema reinforces it

**Cannibalisation:** None (single page).

**Fix recommendations** (longer-term, see Roadmap):
- Add city pages: `/fractional-cfo/london`, `/fractional-cfo/new-york`, `/fractional-cfo/dubai` — each ~600 words, schema'd `LocalBusiness`/`Person` with `areaServed`.
- Add pillar pages: `/work/fractional-cfo`, `/work/ip-strategist`, `/work/ai-operator`.
